# cc-statusline

Installs a pre-built Claude Code status line. Unlike a generator, this ships one finished script, so every machine gets the exact same status line.

```
◈ Opus 5.5 | [■■■■■■■□□□□□□□□□□□□□] 38% (76k/200k) | $1.23 | ↯ high | ⌂ my-repo | ⎇ main
◷ 5h ▰▰▰▰▱▱▱▱▱▱  37% ↻ 2h01m (02:31) | ◷ 7d ▰▰▰▰▰▰▰▰▱▱  81% ↻ 2d7h (10/16 08:02)
```

## Files

| File | Purpose |
|------|---------|
| `scripts/statusline.sh` | The status line itself. Reads Claude Code's session JSON on stdin and prints two colored lines |
| `scripts/install.sh` | Idempotent installer. Copies the script and points `settings.json` at it |

## Installation workflow

1. Let `SKILL_DIR` be the directory containing this SKILL.md.
2. Run the installer:
   ```bash
   bash "${SKILL_DIR}/scripts/install.sh"
   ```
   It will:
   - require `jq` >= 1.6, and print the install command for the current OS if it is missing
   - back up an existing, different `~/.claude/scripts/statusline.sh` to `statusline.sh.bak.<timestamp>`
   - copy `statusline.sh` to `~/.claude/scripts/` and `chmod +x` it
   - back up `~/.claude/settings.json`, then set **only** the `statusLine` key and leave every other setting untouched
   - honor `CLAUDE_CONFIG_DIR` when set
3. If the installer fails because `jq` is missing, offer to install it with the printed command, then re-run.
4. Report what changed (installed or already up to date, and any backup paths). Tell the user the status line refreshes on the next message or new session.

Do not hand-edit `settings.json` or copy the script manually. The installer handles backups and merging.

## What each segment shows

**Line 1**

| Segment | Meaning | Source field |
|---------|---------|--------------|
| `◈ Opus 5.5` | Model name | `model.display_name` |
| `[■■□□] 38% (76k/200k)` | Context used, with tokens used and window size. Green when > 50% remains, yellow at 20–50%, red below 20% | `context_window.*` |
| `$1.23` | Session cost, hidden when it rounds to $0.00 | `cost.total_cost_usd` |
| `↯ high` | Effort level: bold red for high/xhigh/max, yellow for medium, green for low | `effort.level`, falling back to `modelSettings.<model>.effortLevel` / `effortLevel` in settings |
| `❋ Explanatory` | Output style, hidden when default | `output_style.name` |
| `⌂ my-repo` | Repo / directory name (the original repo when inside a worktree) | `worktree.original_repo_dir` → `workspace.current_dir` |
| `⊕ worktree:46a6` | Shown only inside a git worktree | `worktree.name` → `git rev-parse` |
| `⎇ main` | Git branch, yellow when tracked files are modified | `worktree.branch` → `git branch` |

**Line 2**, shown only when Claude Code provides rate-limit data (subscription plans):

| Segment | Meaning |
|---------|---------|
| `◷ 5h ▰▰▱▱ 37% ↻ 2h01m (02:31)` | 5-hour quota used, time until reset, and local reset time |
| `◷ 7d ▰▰▱▱ 81% ↻ 2d7h (10/16 08:02)` | 7-day quota, in the same format |

Quota bars are green below 50%, yellow at 50–79%, and red at 80% or more.

## Customizing

Edit `scripts/statusline.sh` in this skill (so the change can be committed), then re-run `install.sh`. Common changes:

- **Colors**: the `readonly C_*` 24-bit ANSI constants at the top of the file
- **Drop or reorder segments**: the `# Assemble` block, which runs one `parts+=(...)` per segment
- **Context thresholds**: the `remaining -lt 20` / `-lt 50` checks in the progress bar block
- **Hide line 2**: remove the `quota_part` calls near the bottom

## Notes

- The script uses one `jq` process per render and no `awk`/`date` calls, so it stays fast.
- Git calls use `--no-optional-locks` so they never interfere with other git operations.
- It works with macOS's stock bash 3.2, Linux, and Git Bash on Windows. On Windows, it looks for `jq` in the WinGet and scoop install locations when `jq` is not on PATH.
- Originally generated by [webup-statusline](https://github.com/webup/skills-cc), then substantially customized.
